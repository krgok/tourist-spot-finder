# 周辺スポット検索アプリ(観光地調査アプリ)

現在地(または指定した場所)の周辺にある **観光地・飲食店・カフェ・温泉・神社仏閣・美術館** などを調べ、
説明文・評価・営業時間・経路を一覧と地図で確認できる、**ビルド不要の静的 Web アプリ**です。
個人・家族での利用を想定しています。

- 検索・地図・経路: Google Maps Platform(Places API (New)・Routes API・Maps JavaScript API)
- 説明文の補足: Wikipedia(施設の位置と名前が一致する記事だけを採用)
- ログイン・お気に入り・検索履歴: Supabase(Google ログイン、専用スキーマ `tourist_app`)
- ビルド工程・サーバーはありません(`index.html` と `js/*.js` をそのまま配信)

> **このリポジトリは公開(public)です。** Google の API キー・`service_role` キー・パスワードなどの秘密は、
> コードにも設定ファイルにも書かないでください(`js/config.js` の Supabase の URL と **anon キー**は、
> 公開を前提とした値で、データは行レベルセキュリティ(RLS)で守る設計です)。

## 使い方

1. 右上の「⚙ API設定」を開き、Google の API キーを入力して保存します(取得方法は下記)。
2. ジャンル・半径・件数・移動手段を選び、「現在地」または「場所を指定」(地名を入力)で「周辺のスポットを検索」を押します。
   「現在地」を使うには、ブラウザの位置情報の許可が必要です(許可できない場合は「場所を指定」を使えます)。
3. 一覧のカードで「地図で見る」「経路を表示」「お気に入りに追加」ができます。並び替え(おすすめ順・近い順・評価順・レビュー数順)も選べます。
4. 「Google でログイン」すると、お気に入りと検索履歴が保存され、複数の端末で共有されます(未ログインでも検索は使えます)。

## Google の API キーの取得と制限(必ずお読みください)

このアプリは、**利用者自身の API キーを、ブラウザの localStorage に平文で保存**して使います。
キーは Google への通信(写真の URL を含む)にそのまま使われるため、**ブラウザの開発者ツールで見えます。万一ページに悪意あるスクリプトが入り込んだ場合にも盗まれうる**設計です。
そのため、**キーに制限をかけること**が、被害を抑える最も重要な対策です。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成(請求先アカウントの設定が必要です)。
2. 次の 3 つの API を有効化:**Maps JavaScript API**、**Places API (New)**、**Routes API**。
3. 「認証情報」→「認証情報を作成」→「API キー」。**このアプリ専用のキー**を作ってください(他の用途と共用しない)。
4. 作成したキーに、次の制限をかけます。
   - **アプリケーションの制限**:「ウェブサイト(HTTP リファラー)」を選び、このアプリを配信する URL だけを登録
     (例: `https://<ユーザー名>.github.io/*`。ローカル確認用に `http://localhost:8000/*` を足してもよい)。
   - **API の制限**:「キーを制限」で、上の 3 つの API だけを選択。
5. 「割り当て(クォータ)」で、1 日あたりの上限を小さめに設定し、「予算とアラート」で請求額の通知を設定。
6. アプリの「API設定」にキーを貼り付けて保存。使わなくなったら「削除」を押す(共有のパソコンでは入力しないでください)。

リファラー制限を付けても、ブラウザ以外から偽のリファラーで呼び出される可能性はゼロではないため、クォータと予算アラートも合わせて設定してください。
キーの変更後は、地図に反映するためにページを再読み込みしてください。

## Supabase の準備(お気に入り・履歴を使う場合)

既存の Supabase プロジェクトに同居できるよう、専用スキーマ `tourist_app` を使います。**他アプリのスキーマ(`public` を含む)には触れません。**

1. Supabase ダッシュボードの **SQL Editor** で `supabase/schema.sql` を実行します(**初回のみ**。再実行はできません)。
2. 続けて `supabase/migrations/` の SQL を、ファイル名の順に実行します(権限の最小化・入力の制約・件数の上限。**何度実行しても安全**)。
3. **Project Settings → API → Exposed schemas** に `tourist_app` を追加します(デフォルトでは `public` 以外は REST API から見えません)。
4. **Authentication → Sign In / Providers** で Google を有効化し(Google Cloud の OAuth クライアント ID/シークレットは、**ダッシュボードにだけ**入力。リポジトリには書かない)、
   **Authentication → URL Configuration** の Site URL と Redirect URLs を、このアプリの配信 URL だけにします。
5. **家族全員が一度ログインしたら**、Authentication の設定で「Allow new users to sign up」をオフにすることをおすすめします
   (公開 URL から誰でも新規登録できる状態を避けるため。共有プロジェクトの他アプリへの影響を防ぐ意味もあります)。
6. `js/config.js` の `SUPABASE_URL` と `SUPABASE_ANON_KEY`(anon キーは公開前提の値)を、自分のプロジェクトの値にします。
   プロジェクトを変える場合は、`index.html` の CSP(`connect-src`)の Supabase ホストも合わせて変更してください(テストが不一致を検出します)。
7. **`service_role` キーは、絶対にこのリポジトリ・ブラウザに入れないでください。**

共有プロジェクトの他スキーマの状態を確認するための、読み取り専用の SQL を `supabase/audit-queries.sql` に用意しています(SQL Editor で実行して結果を確認します)。

## 公開(配備)の方法

静的ファイルをそのまま配信するだけです。GitHub Pages なら、リポジトリの Settings → Pages で配信するブランチと `/ (root)` を指定します。
JS の更新が利用者のブラウザに反映されるよう、`index.html` と `js/*.js` の `?v=...`(キャッシュ更新用の版)は**全ファイルで同じ値**にしてください(`npm test` が不一致を検出します)。

配備の前に、`docs/audit-2026-11.md` の「配備前に必要な作業」を確認してください。
配備後は、ブラウザの開発者ツールのコンソールに `Refused to ...`(CSP 違反)が出ていないか、検索 → 地図 → 経路 → ログイン → お気に入りを一通り試してください。

## プライバシー:何がどこに保存されるか

| 保存先 | 内容 | 備考 |
|---|---|---|
| **この端末のブラウザ(localStorage)** | Google API キー、並び替え・移動手段の設定 | 端末の外には出ません(Google への通信時に API キーとして使用)。「削除」で消せます |
| **Supabase(ログインした場合のみ)** | **お気に入り**:場所の ID・名前・住所・座標・評価・Google マップの URL・ジャンル・最小限の控え<br>**検索履歴**:**検索地点の座標(「現在地」で検索した場合は、その時の現在地を含みます)**・半径・件数・ジャンル・地点の名前・結果の上位 20 件の名前と評価<br>**アカウント情報**(Supabase Auth):Google アカウントのメールアドレス・名前・アイコン | 自分のデータだけ読み書きできるよう RLS で制限。お気に入りは 1 人 1000 件まで、検索履歴は新しい 500 件だけ保持。アプリ内の「削除」で個別に消せます。アカウントを削除すると、そのデータも連鎖して削除されます |
| 保存しないもの | レビュー本文・投稿者名(お気に入りの控えには保存しません)、写真、現在地の履歴(検索履歴以外) | |

外部サービスへ送られる情報:

- **Google**(Places / Routes / Maps):検索地点の座標、施設の ID、API キー。Google のプライバシーポリシーに従います
- **Wikipedia**:検索結果の施設の座標と名前(利用者の現在地そのものではありません)
- **Supabase**:ログイン・お気に入り・履歴(上の表)
- **esm.sh**(JavaScript ライブラリの配信元):ページの閲覧時に IP アドレス等が通信されます

## 開発

依存パッケージはありません(Node.js 20 以上)。

```bash
npm test         # 単体テスト(node --test)。秘密の混入検査・CSP・アクセシビリティの静的検査を含む
npm run check    # すべての js/*.js の構文確認(ES モジュール)
python3 -m http.server 8000   # http://localhost:8000/ で動作確認(静的サーバー)
bash supabase/tests/local-rls-test.sh   # DB の権限・RLS の検証(使い捨てのローカル PostgreSQL。要 PostgreSQL サーバー一式)
```

- `js/places.js`(絞り込み・並び替え)、`js/wikipedia.js`(照合)、`js/records.js`(DB に保存する行)、`js/http.js`(Google API 呼び出し)などは、画面に依存しない純粋なロジックとして `test/` でテストしています。
- 外部の文字列(施設名・レビュー・URL など)は、`innerHTML` を使わず `textContent` で描画し、リンクは `http(s)` のみ許可しています(`js/safeUrl.js`)。この方針はテストで守られています。
- GitHub Actions(`.github/workflows/ci.yml`)は、構文確認とテストだけを行います(デプロイはしません)。
